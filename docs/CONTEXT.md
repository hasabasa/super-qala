## 1. Что это за проект

**SmartQala** — платформа управления жилым комплексом для рынка Казахстана. Мобильное приложение для жильцов + веб-кабинет для управляющей организации.

- **Кто платит:** управляющая организация (ОСИ), ежемесячная подписка 120–180 ₸ за квартиру
- **Кто пользуется:** жильцы, бесплатно
- **Где:** Астана, пилот на одном ЖК — ноябрь 2026
- **Команда:** основатель пишет бэкенд вместе с Claude Code; Flutter отдан наёмному разработчику
- **Финансирование:** собственные средства + грант Astana Hub. Без инвесторов

Полное описание продукта — [PRODUCT.md](PRODUCT.md). Не пересказывай его здесь, читай там.

## 2. Словарь предметной области

Без этого половина требований непонятна. Термины казахстанские, в других странах устроено иначе.

| Термин | Что значит |
|---|---|
| **ОСИ** | Объединение собственников имущества. Юрлицо, управляющее одним домом. Пришло на смену КСК по реформе ЖКХ. Наш клиент и плательщик |
| **КСК** | Кооператив собственников квартир. Старая форма, местами ещё жива. Может управлять несколькими домами |

| **ЖК** | Жилой комплекс. Может состоять из нескольких домов |
| **Председатель** | Руководитель ОСИ, лицо принимающее решение при продаже. Обычно он же и есть весь «персонал» |
| **Лицевой счёт** | Идентификатор квартиры в биллинге ОСИ. По нему приходит платёж из банка |
| **Начисление** | Одна строка квитанции: услуга, объём, тариф, сумма |
| **Квитанция** | Все начисления квартиры за месяц. Обычно печатается и вешается на дверь |
| **Собрание собственников** | Юридически значимое голосование жильцов. Требует кворума, голос весит по площади квартиры |
| **Поверка** | Обязательная периодическая проверка счётчика. Просрочил — начисляют по нормативу |
| **Kaspi** | Доминирующий финансовый суперапп Казахстана. Через него платят почти всё, включая ЖКХ |
| **БИН** | Бизнес-идентификационный номер юрлица, аналог ИНН |
| **Astana Hub** | Технопарк, выдал грант. Требует отчётности |
| **₸ / тенге** | Валюта. Все суммы в проекте — в тенге, без копеек |

## 4. Принятые решения

Каждое обсуждалось. Причины важнее самих решений — они объясняют, как принимать следующие.

| Решение | Причина |
|---|---|
| **Python 3.12 + FastAPI** | Основная работа проекта — обработка данных: парсинг прайсов и банковских реестров, OCR показаний счётчиков, сверка платежей. Это территория Python. Плюс автогенерация OpenAPI критична: фронтенд пишет посторонний человек |
| **Модульный монолит, не микросервисы** | Команда из двух человек. Микросервисы — налог на коммуникацию, которого нет. Границы модулей проведены жёстко, разрезать можно позже |
| **PostgreSQL + SQLAlchemy 2.0 async + Alembic** | — |
| **Redis на три задачи** | Кэш, pub/sub для чата, брокер arq. Меньше движущихся частей |
| **arq вместо Celery** | Async-native, работает на том же Redis. Отдельный брокер не нужен |
| **WebSocket внутри процесса FastAPI** | Нагрузка (максимум 3 тыс. одновременных) не требует отдельного сервиса. Redis pub/sub заложен сразу, чтобы масштабирование не потребовало переписывания |
| **Flutter для мобильного** | Один подрядчик закрывает iOS и Android. Сильный рынок найма в СНГ. Уже в бюджете |
| **Refine (React) для админок** | Четыре панели вручную — это месяц работы. Генерируем поверх REST |
| **Вход только по SMS, без пароля** | Меньше кода, меньше уязвимостей, привычнее пользователю |
| **Деньги не проходят через нас** | Приём платежей за ЖКУ в пользу третьих лиц — регулируемая деятельность. Платёж идёт напрямую на счёт ОСИ, мы фиксируем факт |
| **ОСИ платит подписку** | Бесплатный продукт не получает ни внимания, ни выполнения обязательств по распространению |
| **Инфраструктура в Казахстане** | Закон о персональных данных требует хранения ПД граждан РК на территории страны |

## 8. Соглашения по коду

### Устройство модуля — одинаковое для всех

```
modules/<name>/
├── models.py      таблицы SQLAlchemy
├── schemas.py     Pydantic: запросы и ответы
├── service.py     бизнес-логика, не знает про HTTP
├── router.py      эндпоинты: валидация → service → ответ
├── repository.py  запросы к БД сложнее CRUD
└── exceptions.py  доменные исключения
```

### Правила

1. Модуль обращается к другому **только через его `service.py`** — никогда напрямую к чужим моделям
2. Циклические зависимости запрещены; общее выносится в `shared/`
3. `router.py` не содержит бизнес-логики. Появился `if` про предметную область — он не на своём месте
4. Исключения — только доменные, из `core/exceptions.py` или модульных. `HTTPException` в сервисах не бросаем
5. Все идентификаторы — UUID
6. Все денежные суммы — целые тенге, без копеек. Никаких float
7. Все datetime — timezone-aware, UTC в базе
8. Комментарии и docstring — по-русски, как в существующем коде
9. Однообразие важнее изящества: код читает внешний разработчик и следующая сессия Claude

### Инструменты

`uv` (зависимости), `ruff` (линт и формат), `mypy --strict`, `pytest` + `pytest-asyncio`. Конфигурация — в `backend/pyproject.toml`.

## 9. Неочевидные места предметной области

Самое важное в документе. Здесь ошибки стоят дорого и всплывают поздно.

**Платежи: заявление и факт — разные сущности.**
`payment_claim` — это «я оплатил» от жильца с приложенным чеком. `payment_fact` — подтверждённый платёж из банковского реестра ОСИ. **Источник истины всегда второй.** Если их смешать, через месяц в системе будут «оплаченные» долги. Ночной воркер сводит одно с другим по лицевому счёту, сумме и дате; несошедшееся уходит на экран ручной сверки. Этот экран нужен всегда — люди платят с чужого номера, не той суммой и за два месяца сразу.

**Подтверждение квартиры — точка наивысшего риска.**
Оно открывает доступ к финансовым данным и к чату соседей. SMS-код подтверждает телефон, но не квартиру. Три пути: код с бумажной квитанции, ручное подтверждение администратором ОСИ, приглашение от подтверждённого собственника (для арендаторов — с урезанными правами, без доступа к начислениям). До подтверждения пользователь не видит ни чата, ни начислений.

**Мультитенантность — на уровне запроса, а не интерфейса.**
Каждая таблица с пользовательскими данными несёт `organization_id`. Фильтр накладывается общей зависимостью из `core/deps.py`. Администратор одного ЖК не должен иметь физической возможности получить данные другого.

**Голосование считается по площади, а не по головам.**
Вес голоса — доля площади квартиры. Один голос от квартиры: `UNIQUE (meeting_id, apartment_id)`. Так требует законодательство о жилищных отношениях. Точные требования к юридической силе протокола сверяются с юристом до релиза.

**Чат — это каналы, а не один общий чат.**
Один чат на 300 человек превращается в помойку за две недели, и люди уходят обратно в WhatsApp. Каналы: объявления ОСИ (только чтение), чат дома, чат подъезда, барахолка.

**Push-уведомления — исчерпаемый ресурс.**
Каждое лишнее уведомление приближает момент, когда пользователь отключит их навсегда. Отсюда ограничение: максимум два рекламных push в неделю на весь ЖК, слоты продаются аукционом.

**Иерархия недвижимости избыточна намеренно.**
`organization → complex → building → entrance → apartment`. Для одного дома выглядит переусложнением, но без неё невозможно обслуживать УК с десятком домов — а это самый ценный клиент.

**Аудитория — плохая связь и старшие возрасты.**
Отсюда: курсорная пагинация вместо offset, компактные ответы, идемпотентность на всех POST с последствиями (клиент будет ретраить), сжатие изображений.

## 10. Что делать дальше

Порядок задан зависимостями, не важностью. Следующая волна не начинается, пока предыдущая не отдаёт рабочий API.

### Волна 1 — ближайшая задача

1. **Инициализировать Alembic**, настроить на async-движок, сделать первую миграцию
2. **Модуль `properties`**: organizations, complexes, buildings, entrances, apartments. Модели, схемы, CRUD для кабинета ОСИ, импорт жильцов из Excel
3. **Модуль `auth`** целиком: `request-code`, `verify-code`, `refresh`, `logout`, `me`. Отправка SMS через провайдер с заглушкой `console` для локальной разработки. Лимиты: 3 кода в час на номер, 10 на IP
4. **Модуль `residents`**: привязка квартиры, три способа подтверждения, обработка заявок администратором
5. **Тесты** на сценарии входа и подтверждения квартиры

**Результат волны:** пользователь регистрируется и привязывается к квартире; в кабинете ОСИ есть список жильцов и импорт. Фронтенд-подрядчик получает живой API вместо моков.

### Дальше

| Волна | Модули | Смысл |
|---|---|---|
| 2 | `billing` | Квитанции, оплата, сверка, архив чеков. **Продукт, за который платит ОСИ** |
| 3 | `requests`, `chat` | Заявки с контролем сроков и каналы. Удерживают жильца |
| 4 | `notifications`, `meters` | Push и показания счётчиков |
| 5 | `voting`, `finance`, `classifieds` | Тариф «Про» и монетизация продвижения |

За пределами MVP: маркетплейс магазинов, мастера, домофония, гостевые пропуска. Описаны в `PRODUCT.md §7`, к разработке не приняты.

## 11. Как работать с пользователем

- **Язык общения — русский.** Код и коммиты — по стандартам, комментарии по-русски
- **Он ждёт рекомендацию, а не список вариантов.** Если есть выбор — назови лучший и объясни почему, не устраивай обзор
- **Возражения приветствуются, если по существу.** Несколько решений в проекте появились именно из спора с исходным планом. Но возражение должно быть конкретным, с цифрами или последствиями
- **Он не профессиональный разработчик бэкенда**, но опытный предприниматель и хорошо считает деньги. Технические решения объясняй через последствия: сроки, стоимость, риск
- **Сроки жёсткие.** Пилот в ноябре 2026, от этой даты зависит финансовая модель. Предложение, удлиняющее разработку, должно окупаться очень явно
