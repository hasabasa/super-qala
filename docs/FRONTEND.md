## 1. Что мы строим

**SmartQala** — мобильное приложение для жителей жилых комплексов Казахстана. Оно заменяет собой хаос из WhatsApp-групп, бумажных квитанций на дверях и звонков председателю ОСИ.

Жилец в одном приложении: видит начисления за коммунальные услуги и оплачивает их, хранит архив всех чеков, оставляет заявки в управляющую организацию и следит за их выполнением, общается с соседями в структурированных каналах, передаёт показания счётчиков, голосует на собраниях собственников и видит, куда ОСИ тратит собранные деньги.

**Кто платит за продукт:** управляющие организации (ОСИ/КСК/УК) по подписке. **Кто пользуется:** жильцы. Из этого следует главное требование к приложению — оно должно быть настолько удобным, чтобы жилец перестал писать в WhatsApp. Если он вернётся в WhatsApp, ОСИ откажется от подписки.

**Первый пилот:** ноябрь 2026, один ЖК в Астане.

## 4. Работа с API

### Базовые адреса

| Окружение | URL |
|---|---|
| Staging | будет выдан до старта работ |
| Production | будет выдан перед релизом |

Префикс всех эндпоинтов: `/api/v1`

### Контракт и генерация клиента

Бэкенд на FastAPI **автоматически публикует OpenAPI-схему** по адресу `/openapi.json`, интерактивная документация — `/docs`.

**Клиент к API генерируется из схемы, а не пишется руками.** Это обязательное требование: контракт будет меняться в процессе, и ручной клиент разойдётся со схемой в первую же неделю.

Пока бэкенд не готов — **подними мок-сервер из той же схемы** (например, Prism) и веди разработку на моках. Не жди готовности эндпоинтов, это заложено в план.

### Аутентификация

Схема — вход по номеру телефона и коду из SMS. **Пароля в системе нет вообще.**

| Токен | Время жизни | Где хранить |
|---|---|---|
| `access_token` | 15 минут | secure storage |
| `refresh_token` | 90 дней | secure storage |

Заголовок: `Authorization: Bearer <access_token>`

**Обязательное поведение интерцептора:**
1. При `401` — один раз попытаться обновить пару токенов через `/auth/refresh`.
2. Параллельные запросы, получившие `401`, ставятся в очередь и повторяются **после одного** обновления. Не допускай гонки с несколькими одновременными refresh — это самая частая ошибка в таких клиентах.
3. Если refresh не удался — очистить хранилище и увести пользователя на экран входа.

### Формат ошибок

Все ошибки API приходят в едином виде:

```json
{
  "error": {
    "code": "rate_limited",
    "message": "Слишком много запросов, попробуйте позже",
    "details": { "retry_after": 120 }
  }
}
```

`message` уже локализован на языке пользователя и **пригоден для показа**. Собственные тексты ошибок придумывать не нужно — кроме сетевых, которых бэкенд не видит («Нет соединения с интернетом», «Сервер не отвечает»).

### Идемпотентность

Запросы, создающие платежи, заявки и сообщения, принимают заголовок `Idempotency-Key` (UUID v4, генерируется клиентом). При ретрае после обрыва связи — **тот же ключ**, иначе пользователь создаст две заявки. Это обязательно.

### Пагинация

Курсорная, не по offset:

```
GET /api/v1/chat/channels/{id}/messages?limit=30&cursor=<opaque>
→ { "items": [...], "next_cursor": "..." | null }
```

Собери их до начала работы над экранами — иначе они разойдутся по стилю:

`AppButton` (primary / secondary / text, состояние загрузки), `AppTextField`, `AppCard`, `StatusBadge`, `AppScaffold`, `LoadingView`, `EmptyView` (иллюстрация + текст + действие), `ErrorView` (текст + «Повторить»), `AppBottomSheet`, `ConfirmDialog`, `AppRefreshIndicator`.

Любой экран со списком обязан корректно показывать **загрузку** (скелетоны, не спиннер по центру), **пустоту** (осмысленный текст и действие, а не «Нет данных») и **ошибку** (причина и кнопка «Повторить»). Экран без этих трёх состояний не принимается.

## 6. Экраны

Разбиты по волнам. Волны соответствуют готовности бэкенда — работай строго по порядку.

### Волна 1. Вход и привязка квартиры

Самая ответственная часть приложения. Привязка квартиры открывает доступ к финансовым данным и к чату соседей, поэтому здесь недопустимы срезанные углы.

**1.1. Онбординг** — 3 экрана-слайда: «Все квитанции в телефоне», «Заявки в ОСИ без звонков», «Соседи и объявления в одном месте». Кнопка «Пропустить». Показывается один раз.

**1.2. Ввод телефона**
- Маска `+7 (7XX) XXX-XX-XX`, клавиатура числовая
- Чекбокс согласия на обработку персональных данных со ссылкой на политику — **обязателен по закону РК**, без него кнопка неактивна
- `POST /auth/request-code`

**1.3. Ввод кода из SMS**
- 4 поля, автофокус, автозаполнение из SMS (SMS Retriever на Android, `autofillHints` на iOS)
- Таймер повторной отправки 60 секунд
- Показ ошибки при неверном коде, счётчик оставшихся попыток
- `POST /auth/verify-code` → токены + флаг `is_new_user`

**1.4. Профиль** (только для нового пользователя) — имя, фамилия, необязательное фото. `PATCH /users/me`

**1.5. Привязка квартиры** — пошагово:
1. Поиск ЖК по названию или адресу
2. Выбор дома → подъезда → номера квартиры
3. Кто вы: собственник / арендатор / член семьи
4. Подтверждение — один из способов:
   - **Код с квитанции** (быстро, автоматически)
   - **Заявка администратору ОСИ** (проверяется вручную, до 24 часов)
5. Экран ожидания со статусом заявки

Пользователь без подтверждённой квартиры видит приложение в ограниченном режиме: доступен только профиль и статус заявки. Это важно — до подтверждения он не должен видеть ни чат, ни начисления.

**1.6. Главный экран** — вертикальный список карточек:
- Шапка: название ЖК, номер квартиры, иконка уведомлений со счётчиком
- **Карточка задолженности**: сумма к оплате, срок, кнопка «Оплатить». Зелёная, если долга нет
- **Мои заявки**: количество активных, последний статус
- **Чат ЖК**: число непрочитанных, последнее объявление ОСИ
- **Показания счётчиков**: напоминание в период сдачи
- **Объявления**: 2–3 свежих
- Ряд экстренных кнопок: 102, 103, 101, диспетчер ЖК (открывают системный набор номера)

Состав карточек различается для разных ЖК (тарифы отличаются набором модулей) — **порядок и видимость приходят с бэкенда**, не зашивай их в код.

### Волна 2. Квитанции и оплата

**2.1. Список квитанций** — по периодам, статус цветом: к оплате / оплачено / просрочено. Фильтр по году.

**2.2. Детали квитанции** — разбивка по услугам (содержание, вода, электричество, вывоз мусора и т. д.), объём, тариф, сумма. Итог, срок оплаты. Кнопка «Оплатить». Кнопка «Скачать PDF».

**2.3. Оплата** — ключевой сценарий, важно не ошибиться:
1. Нажатие «Оплатить» открывает Kaspi по deep link с предзаполненными реквизитами
2. При возврате в приложение — экран «Вы оплатили?» с вариантами «Да» / «Ещё нет»
3. При «Да» — предложение приложить чек (PDF или скриншот из галереи)
4. Квитанция переходит в статус **«Ожидает подтверждения»**
5. После сверки с реестром ОСИ (обычно к следующему утру) — статус **«Оплачено»**

Статус «Ожидает подтверждения» должен быть визуально явно отличим от «Оплачено». Пользователь обязан понимать, что платёж ещё не сверен. Это принципиально: деньги идут напрямую на счёт ОСИ, а не через нас, и мы узнаём о платеже только из банковского реестра.

**2.4. Архив чеков** — все платежи за всё время, фильтр по году и услуге, просмотр и шеринг PDF. Это наша ключевая ценность против оплаты напрямую в Kaspi, экран должен быть удобным.

### Волна 3. Заявки и чат

**3.1. Список заявок** — вкладки «Активные» / «Завершённые», статус, срок SLA, категория.

**3.2. Создание заявки** — категория, описание, до 5 фото (сжатие перед отправкой обязательно), место (моя квартира / подъезд / двор). После отправки — обещанный срок выполнения.

**3.3. Детали заявки** — статусная лента (принята → в работе → выполнена), переписка с ОСИ, фото. После выполнения — оценка от 1 до 5 звёзд.

**3.4. Список каналов** — «Объявления ОСИ» (только чтение), «Чат дома», «Чат подъезда», «Барахолка». Непрочитанные, последнее сообщение.

**3.5. Чат** — WebSocket, текст и фото, ответ на сообщение, закреплённые сообщения от ОСИ. Постраничная догрузка истории вверх. Обязательно: очередь неотправленных сообщений при обрыве связи с автоматической отправкой при восстановлении, индикатор состояния соединения.

### Волна 4. Уведомления и счётчики

**4.1. Центр уведомлений** — история, переход к объекту по нажатию.
**4.2. Настройки уведомлений** — по категориям.
**4.3. Список счётчиков** — тип, номер, последнее показание, срок поверки.
**4.4. Передача показаний** — фото шкалы, распознанное значение подставляется в поле, пользователь **подтверждает или исправляет вручную**. Валидация: новое значение не меньше предыдущего, предупреждение при аномальном расходе.

### Волна 5. Тариф «Про» и объявления

**5.1. Собрания** — список, повестка, бюллетень, результаты в реальном времени, протокол PDF.
**5.2. Финансы ОСИ** — доходы и расходы по месяцам, категории, приложенные документы, диаграмма.
**5.3. Объявления** — лента, фильтры, карточка (контакт открывается по нажатию), создание, «Мои объявления», платное продвижение.

## 7. Навигация

```
/onboarding
/auth/phone
/auth/code
/auth/profile
/link-apartment              (мастер привязки)
/link-apartment/pending

/  (Shell с нижней навигацией)
├── /home
├── /billing        → /billing/:id
├── /requests       → /requests/new, /requests/:id
├── /chat           → /chat/:channelId
└── /profile        → /profile/settings, /profile/apartments, /profile/notifications
```

Нижняя навигация — 5 пунктов. Guard'ы: без токена → `/auth/phone`; с токеном, но без подтверждённой квартиры → `/link-apartment/pending`.

Deep links из push-уведомлений обязаны открывать конкретный объект: `smartqala://billing/{id}`, `smartqala://requests/{id}`, `smartqala://chat/{channelId}`.

## 8. Локализация

Два языка с первого дня: русский и казахский. Все строки — в ARB-файлах, **ни одной строки в коде**. Приёмка включает проверку переключением языка.

Форматирование: суммы `1 234 567 ₸` (неразрывный пробел разделителем), даты `дд.мм.гггг`, телефон `+7 (777) 123-45-67`.

Казахские переводы предоставим мы — оставляй ключи и заглушки.

## 9. Поведение при плохой сети

Это требование приёмки, а не «сделаем потом»:

- Кэширование последних загруженных данных (drift): квитанции, заявки, история чата открываются офлайн в режиме чтения
- Баннер «Нет соединения» вверху экрана, а не диалог поверх
- Автоматический повтор запросов с экспоненциальной задержкой (3 попытки, только для идемпотентных)
- Очередь исходящих сообщений чата с отправкой при восстановлении связи
- Все изображения сжимаются перед загрузкой: максимум 1920 px по длинной стороне, JPEG качества 80
- Скелетоны вместо спиннеров — воспринимается быстрее

## 10. Push-уведомления

Firebase Cloud Messaging. Токен отправляется на бэкенд после входа и при каждом обновлении: `POST /devices`.

Типы: новая квитанция, приближение срока оплаты, подтверждение платежа, смена статуса заявки, объявление ОСИ, новое сообщение в чате, напоминание о показаниях, начало голосования.

Обработка обязательна во всех трёх состояниях: приложение открыто, свёрнуто, закрыто. При нажатии — переход к конкретному объекту через deep link.

## 14. Нерешённые продуктовые вопросы

Решить до реализации соответствующих экранов:

1. **Механика оплаты через Kaspi** — deep link или QR. Зависит от того, подключена ли пилотная ОСИ как поставщик услуг. Блокер, влияет на экран 2.3
2. **Несколько квартир у одного пользователя** — нужен ли переключатель в MVP (актуально для собственников нескольких квартир)
3. **Модерация чата** — какие действия доступны жильцу: жалоба на сообщение, скрытие пользователя
4. **PDF квитанции** — генерирует бэкенд или клиент отображает HTML
